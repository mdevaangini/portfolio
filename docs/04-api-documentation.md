# 04 — API (Node.js + Express)

[← 03 Frontend](03-frontend-documentation.md) · [Docs home](README.md) · Next: [05 — Database](05-database-documentation.md)

## In plain English

The API is a small program that waits for requests. When a request arrives, for example "give me the projects in the Payments category", it checks the request makes sense, asks the database through Prisma, and replies with JSON. If the request is wrong, it says so with a clear message and a status code.

## A. Architecture

### Folder structure

```text
api/
├── .env                 secret settings (never committed)
├── .env.example         template of the settings, safe to commit
├── package.json         dependencies + "npm run dev"
├── tsconfig.json        TypeScript settings
├── prisma7.config.ts    settings for the Prisma commands (not used at runtime)
├── prisma/
│   ├── schema.prisma    description of the tables
│   └── migrations/      history of structure changes
├── generated/prisma/    code generated by `npx prisma generate` (git-ignored)
└── src/
    ├── server.ts        starts the server — nothing else
    ├── app.ts           middleware + routes (no listen → testable)
    ├── routes.ts        main router: one line per feature
    ├── config/env.ts    reads and checks .env
    ├── db/prisma.ts     the one shared Prisma Client
    ├── middleware/
    │   ├── not-found.ts     404 for unknown URLs
    │   └── error-handler.ts 500 for anything that throws
    └── modules/
        └── projects/
            ├── projects.routes.ts      URL → handler
            ├── projects.controller.ts  validate, status codes, response
            └── projects.service.ts     data access with Prisma
```

Also present: `readme.txt` (the owner's learning notes) and `_prisma-backup/` (an earlier, parked Prisma attempt, not used by the app).

**Rule of the layers:** only **services** touch the database; only **controllers** touch `req`/`res`. "Controller" and "service" are a code-organisation convention, not Express features.

### Start-up sequence

1. `npm run dev` → `tsx watch --env-file=.env src/server.ts`. `tsx` runs TypeScript directly and restarts on save; `--env-file` loads `.env` into `process.env`.
2. `server.ts` imports `app.ts`, which imports `config/env.ts`. `env.ts` reads `DATABASE_URL` and **throws at start-up if it is missing**.
3. `db/prisma.ts` creates the Prisma Client with the `PrismaPg` adapter (once).
4. `app.ts` registers middleware and routes in order.
5. `server.ts` calls `app.listen(env.port)` and logs `API running at http://localhost:3000`.

### Request lifecycle (`api/src/app.ts`)

```ts
app.use(cors({ origin: env.corsOrigin })); // 1. may this site read the response?
app.use(express.json());                    // 2. parse a JSON body into req.body
app.use("/api", apiRouter);                 // 3. feature routes
app.use(notFound);                          // 4. nothing matched → 404
app.use(errorHandler);                      // 5. something threw → 500
```

Express runs these **top to bottom** for every request. The first one that sends a response ends the request. That's why `notFound` and `errorHandler` come last.

The URL is assembled in pieces: `app.ts` mounts `/api`, `routes.ts` mounts `/projects`, and `projects.routes.ts` defines `/`, `/categories` and `/:id`.

### Configuration (`api/src/config/env.ts`)

| Variable | Required | Default | Used for |
|---|---|---|---|
| `DATABASE_URL` | **Yes** | — | Prisma connection (`db/prisma.ts`) |
| `PORT` | No | `3000` | `server.ts` |
| `CORS_ORIGIN` | No | `http://localhost:4200` | `cors()` in `app.ts` |

### Error handling

- **400**: invalid input, decided in controllers.
- **404**: unknown id (controller) or unknown route (`not-found.ts`).
- **500**: any thrown error. Express 5 forwards rejected `async` handlers to `error-handler.ts`, which **logs the full error in the terminal** and sends only a generic message, so internal details never reach the browser.

### Authentication

None. All endpoints are public and read-only.

## B. Endpoint reference

All responses are JSON. Base URL in development: `http://localhost:3000`.

### `GET /api/projects` — list projects

| | |
|---|---|
| Purpose | One page of projects, optionally filtered |
| Handler | `listProjects` in `projects.controller.ts` → `findProjects` in `projects.service.ts` |
| Auth | None |

**Query parameters**

| Name | Type | Default | Rules | Meaning |
|---|---|---|---|---|
| `limit` | integer | 10 | 1–50 | Maximum number of projects |
| `offset` | integer | 0 | ≥ 0 | Number to skip first |
| `title` | string | — | trimmed; empty = ignored | Title **contains** this text, case-insensitive |
| `category` | string | — | trimmed; empty = ignored | Category **equals** this, case-insensitive |

**Example request:** `GET /api/projects?category=Payments`

**200 response** (shape verified in code; field values illustrative):

```json
{
  "data": [
    {
      "id": 1,
      "title": "Flexipay — Digital Payments & Mobile Money Platform",
      "summary": "…",
      "description": "…",
      "category": "Payments",
      "imageUrl": null,
      "liveUrl": null,
      "repoUrl": null,
      "displayOrder": 1
    }
  ],
  "total": 1,
  "limit": 10,
  "offset": 0
}
```

`total` counts **all** matches, not just this page. Ordering is by `displayOrder` ascending.

**Errors**

| Status | When | Body |
|---|---|---|
| 400 | `limit` not an integer in 1–50 | `{ "error": "limit must be a whole number between 1 and 50" }` |
| 400 | `offset` not an integer ≥ 0 | `{ "error": "offset must be a whole number of 0 or more" }` |
| 500 | Database or other failure | `{ "error": "Something went wrong. Please try again later." }` |

**Database work:** `findMany` with `where`/`orderBy`/`take`/`skip`, plus `count` with the same `where`, run together in `prisma.$transaction([...])` so the page and the total describe the same moment.

### `GET /api/projects/categories` — list categories

| | |
|---|---|
| Purpose | The distinct categories in use; feeds the filter chips |
| Handler | `listCategories` → `findCategories` |
| Parameters | None |

**200 response:**

```json
["Banking", "Lending", "Payments"]
```

Sorted alphabetically; projects with no category are excluded. Equivalent SQL: `SELECT DISTINCT category FROM projects WHERE category IS NOT NULL ORDER BY category`.

> Route order matters: `/categories` is declared **before** `/:id` in `projects.routes.ts`. Otherwise `/:id` would catch the word "categories" and return 400.

### `GET /api/projects/:id` — one project

| | |
|---|---|
| Handler | `getProject` → `findProjectById` |
| Path parameter | `id`, a positive integer |

| Status | When | Body |
|---|---|---|
| 200 | Found | A single `Project` object (same fields as above) |
| 400 | `id` not a positive integer, e.g. `/api/projects/abc` | `{ "error": "id must be a positive whole number" }` |
| 404 | No project with that id, e.g. `/api/projects/999` | `{ "error": "Project 999 not found" }` |

Database work: `prisma.project.findUnique({ where: { id } })`.

### Any other URL

`404 { "error": "Route not found: GET /api/hello" }`.

## C. One flow in context: the category filter

1. **Route** (`projects.routes.ts`): `projectsRouter.get("/", listProjects)`.
2. **Controller** (`listProjects`): reads `req.query.category` (only if it's a string), trims it, validates `limit`/`offset`, then calls the service with `category: category || undefined`.
3. **Service** (`findProjects`): builds the filter only from the values provided:

```ts
const where: Prisma.ProjectWhereInput = {
  ...(title && { title: { contains: title, mode: "insensitive" } }),
  ...(category && { category: { equals: category, mode: "insensitive" } }),
};
```

4. **Database**: Prisma sends roughly `SELECT … FROM projects WHERE category ILIKE 'Payments' ORDER BY display_order LIMIT 10 OFFSET 0`, plus a matching `COUNT(*)`. Values are sent as **parameters**, never pasted into the SQL text.
5. **Response**: the service returns `{ data, total, limit, offset }`; the controller sends it with `res.json(result)`.
6. **Errors**: invalid `limit`/`offset` stop at step 2 with a 400, and Prisma is never called. A database failure throws at step 4 and reaches `error-handler.ts` → 500.
