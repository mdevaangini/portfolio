D. DECISIONS AND RATIONALE (do not reopen unless the user asks)
==============================================================================
  - Stack: Angular 22 (frontend), Node + Express 5 + TypeScript (API),
    PostgreSQL 18 (DB). Express chosen over NestJS: NestJS hides the
    request→response flow the user wants to learn.
  - One folder "portfolio" with api/ and web/ (no monorepo tooling).
  - Vertical slice first; deployment postponed by the user (decided later).
  - ORM: Prisma 7 (not Drizzle; not Prisma 8 RC). Raw SQL was learned first.
  - API architecture: feature modules; server.ts (start only) / app.ts
    (middleware + routes, testable) / routes.ts (one line per feature) /
    modules/<feature>/{routes,controller,service}. Services live INSIDE their
    feature folder (no central services folder). No repository layer
    (over-engineering for a portfolio). Only services touch the DB; only
    controllers touch req/res.
  - Validation in the controller; 400 for bad input, 404 for missing items.
  - Settings via config/env.ts (required DATABASE_URL checked at startup;
    PORT default 3000; CORS_ORIGIN default http://localhost:4200).
  - DB naming: snake_case in DB, camelCase in code/JSON via @map/@@map.
  - Prisma schema/migrations: structure changes = edit schema → migrate dev
    → generate. Data changes = pgAdmin / Prisma Studio / Prisma in code.
    Never change structure by hand in pgAdmin any more.
  - Projects filter UX: category CHIPS (Option B) instead of a search box
    (only 3 projects; chips look better to recruiters). Chips come from
    GET /api/projects/categories so they don't disappear when filtered.
  - Frontend: one component per section; signal inputs; OnPush; @for/@if/
    @switch; httpResource for GET; linkedSignal keeps the previous list
    visible (dimmed) while a new filter loads; CSS scroll-driven .reveal
    animation; all motion behind prefers-reduced-motion.
  - Plan "A": build all sections statically first, then move Skills /
    Experience into the DB later (JOIN lesson).
  - Design: Navy Professional; title on site = "Frontend Engineer" (matches
    CV); phone number NOT shown publicly; no availability badge.
