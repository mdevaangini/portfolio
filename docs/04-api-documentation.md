# 04 — API (Node.js + Express)

[← 03 Frontend](03-frontend-documentation.md) · [Docs home](README.md) · Next: [05 — Database](05-database-documentation.md)

## In plain English

The API is a small program that waits for requests. When a request arrives, for example "give me the skills" or "please save this message", it checks the request makes sense, asks the database through Prisma, and replies with JSON. If the request is wrong, it says so with a clear message and a status code.

## A. Architecture

### Folder structure

```text
api/
├── .env                 secret settings (never committed)
├── .env.example         template of the settings, safe to commit
├── package.json         dependencies + scripts (dev, build, start, seed …)
├── tsconfig.json        TypeScript settings for type-checking (no output)
├── tsconfig.build.json  TypeScript settings for the production build (output in dist/)
├── prisma.config.ts     settings for the Prisma commands (not used at runtime)
├── prisma/
│   ├── schema.prisma    description of the tables
│   ├── seed.ts          fills experience + skills with CV data
│   └── migrations/      history of structure changes (4 so far)
├── generated/prisma/    code generated by `npx prisma generate` (git-ignored)
├── dist/                production JavaScript from `npm run build` (git-ignored)
└── src/
    ├── server.ts        starts the server — nothing else
    ├── app.ts           middleware + routes (no listen → testable)
    ├── routes.ts        main router: one line per feature
    ├── config/env.ts    reads and checks .env
    ├── db/prisma.ts     the one shared Prisma Client
    ├── middleware/
    │   ├── not-found.ts     404 for unknown URLs
    │   └── error-handler.ts 500 for anything that throws
    └── modules/
        ├── projects/    projects.routes.ts · projects.controller.ts · projects.service.ts
        ├── experience/  experience.routes.ts · experience.controller.ts · experience.service.ts
        ├── skills/      skills.routes.ts · skills.controller.ts · skills.service.ts
        └── contact/     contact.routes.ts · contact.controller.ts · contact.service.ts · contact.email.ts
```

Also present: `readme.txt` (the owner's learning notes) and `_prisma-backup/` (an earlier, parked Prisma attempt; git-ignored, not used by the app).

**Rule of the layers:** only **services** touch the database; only **controllers** touch `req`/`res`. "Controller" and "service" are a code-organisation convention, not Express features. Adding a feature = a new folder in `modules/` + one line in `routes.ts`.

### Start-up sequence

1. `npm run dev` → `tsx watch --env-file=.env src/server.ts`. `tsx` runs TypeScript directly and restarts on save; `--env-file` loads `.env` into `process.env`.
2. `server.ts` imports `app.ts`, which imports `config/env.ts`. `env.ts` reads `DATABASE_URL` and **throws at start-up if it is missing**.
3. `db/prisma.ts` creates the Prisma Client with the `PrismaPg` adapter (once).
4. `app.ts` registers middleware and routes in order.
5. `server.ts` calls `app.listen(env.port)` and logs `API running at http://localhost:3000`.

On **Vercel**, `server.ts` is not used: Vercel imports the **default export** of `src/app.ts` and runs the app as one serverless function. Before that, its build runs `vercel-build` (`prisma generate && prisma migrate deploy`). On a classic Node host the same code runs as plain JavaScript: `npm run build` then `npm start`. See [09](09-deployment-and-configuration.md).

### Request lifecycle (`api/src/app.ts`)

```ts
app.use(cors({ origin: env.corsOrigin })); // 1. may this site read the response?
app.use(express.json());                    // 2. turn a JSON body into req.body (used by POST /contact)
app.use("/api", apiRouter);                 // 3. feature routes
app.use(notFound);                          // 4. nothing matched → 404
app.use(errorHandler);                      // 5. something threw → 500
```

Express runs these **top to bottom** for every request. The first one that sends a response ends the request. That's why `notFound` and `errorHandler` come last.

The URL is assembled in pieces: `app.ts` mounts `/api`, `routes.ts` mounts `/projects`, `/experience`, `/skills` and `/contact`, and each `*.routes.ts` defines the rest.

### Configuration (`api/src/config/env.ts`)

| Variable | Required | Default | Used for |
|---|---|---|---|
| `DATABASE_URL` | **Yes** | — | Prisma connection (`db/prisma.ts`) |
| `PORT` | No | `3000` | `server.ts` |
| `CORS_ORIGIN` | No | `http://localhost:4200` | `cors()` in `app.ts`. **Live:** the website's address |
| `DATABASE_URL_UNPOOLED` | No | — | Only on Vercel/Neon: direct connection used by Prisma commands (`prisma.config.ts`) |
| `RESEND_API_KEY` | No | empty | Secret key for Resend; empty = no notification emails |
| `NOTIFY_EMAIL` | No | empty | Where notifications go (the address the Resend account was created with) |

### Scripts (`api/package.json`)

| Script | Runs | When |
|---|---|---|
| `npm run dev` | `tsx watch --env-file=.env src/server.ts` | Everyday development |
| `npm run seed` | `tsx --env-file=.env prisma/seed.ts` | Refill experience + skills |
| `npm run build` | `prisma generate && tsc -p tsconfig.build.json` | Make production JavaScript in `dist/` (other hosts) |
| `npm run vercel-build` | `prisma generate && prisma migrate deploy` | Run by **Vercel** on every deploy |
| `npm start` | `node dist/src/server.js` | Production (the host provides the settings) |
| `npm run start:local` | `node --env-file=.env dist/src/server.js` | Try the production build locally |
| `npm run db:migrate` | `prisma migrate deploy` | Apply migrations to a (production) database |
| `npm run typecheck` | `tsc -p tsconfig.json` | Check types without building |

### Error handling

- **400**: invalid input, decided in controllers.
- **404**: unknown id (controller) or unknown route / wrong method (`not-found.ts`).
- **500**: any thrown error. Express 5 forwards rejected `async` handlers to `error-handler.ts`, which **logs the full error in the terminal** and sends only a generic message, so internal details never reach the browser.

### Authentication

None. Reading endpoints are public. The only write endpoint (`POST /api/contact`) is public by design, protected by validation, length limits and a spam trap.

## B. Endpoint reference

All responses are JSON. Base URL in development: `http://localhost:3000`.

| Method + path | Purpose | Success |
|---|---|---|
| `GET /api/projects` | One page of projects, optionally filtered | 200 |
| `GET /api/projects/categories` | Distinct categories (for the chips) | 200 |
| `GET /api/projects/:id` | One project | 200 |
| `GET /api/experience` | All jobs, newest first | 200 |
| `GET /api/skills` | All skill groups, each with its skills | 200 |
| `POST /api/contact` | Save a contact message | **201** |

### `GET /api/projects` — list projects

Handler: `listProjects` in `projects.controller.ts` → `findProjects` in `projects.service.ts`.

| Query parameter | Type | Default | Rules | Meaning |
|---|---|---|---|---|
| `limit` | integer | 10 | 1–50 | Maximum number of projects |
| `offset` | integer | 0 | ≥ 0 | Number to skip first |
| `title` | string | — | trimmed; empty = ignored | Title **contains** this text, case-insensitive |
| `category` | string | — | trimmed; empty = ignored | Category **equals** this, case-insensitive |

**200 response** (field values illustrative):

```json
{
  "data": [
    {
      "id": 1,
      "title": "Flexipay — Digital Payments & Mobile Money Platform",
      "summary": "…",
      "description": "…",
      "category": "Payments",
      "imageUrl": null,
      "liveUrl": null,
      "repoUrl": null,
      "displayOrder": 1
    }
  ],
  "total": 1,
  "limit": 10,
  "offset": 0
}
```

`total` counts **all** matches, not just this page. Ordering is by `displayOrder` ascending.

| Status | When | Body |
|---|---|---|
| 400 | `limit` not an integer in 1–50 | `{ "error": "limit must be a whole number between 1 and 50" }` |
| 400 | `offset` not an integer ≥ 0 | `{ "error": "offset must be a whole number of 0 or more" }` |
| 500 | Database or other failure | `{ "error": "Something went wrong. Please try again later." }` |

Database work: `findMany` + `count` with the same `where`, run together in `prisma.$transaction([...])` so the page and the total describe the same moment.

### `GET /api/projects/categories`

**200:** `["Banking", "Lending", "Payments"]` — sorted; projects with no category are excluded.

> Route order matters: `/categories` is declared **before** `/:id` in `projects.routes.ts`. Otherwise `/:id` would catch the word "categories" and return 400.

### `GET /api/projects/:id`

| Status | When | Body |
|---|---|---|
| 200 | Found | A single `Project` object |
| 400 | `id` not a positive integer, e.g. `/api/projects/abc` | `{ "error": "id must be a positive whole number" }` |
| 404 | No project with that id, e.g. `/api/projects/999` | `{ "error": "Project 999 not found" }` |

### `GET /api/experience` — work experience

Handler: `listExperiences` → `findExperiences` (`prisma.experience.findMany({ orderBy: { startDate: "desc" } })`). No parameters, so the controller has nothing to validate.

**200 response** (first item shown):

```json
[
  {
    "id": 1,
    "title": "Software Engineer",
    "company": "Happiest Minds",
    "companyNote": "formerly PureSoftware",
    "location": "Noida",
    "summary": "Own end-to-end feature delivery on Arttha, …",
    "startDate": "2024-05-01T00:00:00.000Z",
    "endDate": null
  }
]
```

`endDate: null` means the current job. Dates are text in JSON; Angular formats them.

### `GET /api/skills` — skill groups with their skills

Handler: `listSkillGroups` → `findSkillGroups`. One call returns each group **together with** its skills, thanks to the link between the two tables:

```ts
prisma.skillGroup.findMany({
  orderBy: { displayOrder: "asc" },
  select: {
    id: true, name: true, isCore: true,
    skills: { orderBy: { displayOrder: "asc" }, select: { id: true, name: true } },
  },
});
```

`select` picks which fields to send (like choosing columns); asking for `skills` inside it makes Prisma use `skills.group_id` to fetch and nest each group's skills.

**200 response** (first group shown):

```json
[
  {
    "id": 1,
    "name": "Frontend",
    "isCore": true,
    "skills": [
      { "id": 1, "name": "Angular (15+)" },
      { "id": 2, "name": "TypeScript" }
    ]
  }
]
```

### `POST /api/contact` — save a contact message

Handler: `sendMessage` → `createMessage` (`prisma.message.create`) → `notifyNewMessage` (email via Resend). This is the API's only **write**.

**Request body** (JSON, `Content-Type: application/json`):

```json
{ "name": "Asha", "email": "asha@company.com", "message": "Hello!", "website": "" }
```

| Field | Rules (after trimming spaces) |
|---|---|
| `name` | required, ≤ 100 characters |
| `email` | required, looks like `something@something.something`, ≤ 254 characters |
| `message` | required, ≤ 2000 characters |
| `website` | **spam trap**: a field hidden from people. If it has any text, the API answers 201 but saves nothing |

| Status | When | Body |
|---|---|---|
| **201** | Saved | `{ "ok": true, "id": 7, "createdAt": "2026-10-22T10:54:50.796Z" }` |
| 400 | One or more fields invalid (all problems reported at once) | `{ "error": "Please check the form.", "fields": { "email": "Please enter a valid email." } }` |
| 404 | Wrong method, e.g. `GET /api/contact` | `{ "error": "Route not found: GET /api/contact" }` |
| 500 | Database or other failure | generic message |

Why **201** and not 200: 201 "Created" is the standard answer when something new was stored. `id` and `created_at` are filled in by the database itself.

### Any other URL

`404 { "error": "Route not found: GET /api/hello" }`.

## C. Two flows in context

### Reading: the category filter

1. **Route**: `projectsRouter.get("/", listProjects)`.
2. **Controller**: reads `req.query.category` (only if it's a string), trims it, validates `limit`/`offset`, then calls the service with `category: category || undefined`.
3. **Service**: builds the filter only from the values provided:

```ts
const where: Prisma.ProjectWhereInput = {
  ...(title && { title: { contains: title, mode: "insensitive" } }),
  ...(category && { category: { equals: category, mode: "insensitive" } }),
};
```

4. **Database**: Prisma sends roughly `SELECT … FROM projects WHERE category ILIKE $1 ORDER BY display_order LIMIT 10 OFFSET 0`, plus a matching `COUNT(*)`. Values are sent as **parameters**, never pasted into the SQL text.
5. **Response**: `res.json({ data, total, limit, offset })`.

### Writing: a contact message

1. **Route**: `contactRouter.post("/", sendMessage)` — `post`, because it *sends* data.
2. **Controller**: `express.json()` has already turned the body into `req.body`. The controller trims each field, checks the spam trap, then collects every problem into a `fields` object. Any problem → 400 and stop.
3. **Service**: `prisma.message.create({ data, select: { id: true, createdAt: true } })` → roughly `INSERT INTO messages (name, email, message) VALUES ($1, $2, $3) RETURNING id, created_at`.
4. **Notify**: `notifyNewMessage()` in `contact.email.ts` asks **Resend** (an email-sending service) to email the owner:
   - from `Portfolio <onboarding@resend.dev>` (Resend's shared sender, allowed because it only emails the account owner), to `NOTIFY_EMAIL`;
   - subject `New portfolio message from {name}`, **plain text only** (a visitor can't inject links or HTML);
   - `replyTo` = the visitor's email, so clicking **Reply** in Gmail answers them;
   - it **never fails the request**: problems are only logged. Look for one line in the terminal (or Vercel → Logs): `[email] sent to … (id …)`, `[email] failed: …`, or `[email] skipped: …` (settings missing).
5. **Response**: `res.status(201).json({ ok: true, id, createdAt })`.

Why an email service at all: emails sent straight from a server are usually blocked or marked as spam; Resend is a trusted sender. Free tier: 100 emails/day, 3,000/month.
